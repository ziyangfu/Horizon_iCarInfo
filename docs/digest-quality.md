# 底盘日报的采集、评分与筛选诊断

本分支将日报内容分为行业资讯、前沿论文和前瞻专利。每日运行一次，
允许各类内容采用不同的回看窗口；日报明确标注窗口，并保留真实发表日期。

## 为什么采集很多，日报仍很少

旧流程依次执行 URL 去重、模型分析、分数阈值、同事件去重和板块限额。
采集总数包括不相关的社区讨论和其他噪声，并不等于可用底盘资讯数。
评分失败的条目没有有效分数，也会被过滤。

旧评分提示词要求多个主题或主题与厂商组合命中，且可能因文章出现销量、
价格等词而将整篇技术报道判为噪声。正文默认只取前 1000 字，容易丢失
关键技术信息。默认配置的 6 分门槛还会排除部分有用的渐进工程进展。

2026-10-28 的旧日报没有保存原始 118 条内容与逐条评分，无法准确追溯
每条内容被排除的具体原因。此次改动开始保存诊断，避免继续凭最终条数猜测。

## 当前底盘配置

默认入口读取 `data/config.json`；`--config data/config.icar.json` 读取版本管理
中的底盘配置。此次两者同步了以下参数：

| 内容 | 采集窗口 | 入选阈值 | 每期限额 |
|---|---|---|---|
| 行业资讯 | Google News 近 72 小时，其他来源默认近 24 小时 | 4.0 | 最多 12 条 |
| 前沿论文 | 近 168 小时（7 天） | 4.0 | 最多 5 篇 |
| 前瞻专利 | 近 168 小时（7 天） | 4.0 | 最多 3 项 |

全期最多 20 条。限额是上限，不是凑数目标；没有足够证据或相关内容时，
条数仍可能少于上限。连续日报可能包含同一周内的论文与专利，窗口标识
表示近期追踪，不表示它们都是当天新发表。

Google News 的 `queries` 支持多条检索，按查询轮流合并结果并去重，
共享 `max_results` 上限，避免单一查询占满采集池。`query` 保留为单查询配置。
`lookback_hours` 支持 Google News、arXiv、Crossref 和专利；省略时使用
命令行／全局采集窗口，配置后使用两者中更长的窗口。

评分由本地模型执行。P0 或 P1 的实质性底盘内容可以独立满足相关性要求，
不再强制命中知名供应商或第二个主题。白名单权重是相关性参考，实际得分
依照技术内容和证据质量判断。泛营销、纯销量、无底盘上下文的自动驾驶内容
仍应排除。单纯出现降价、量产、AI 等词不会否决实质性技术内容。

三个底盘 Profile 的分析预算提升到 4000 字符，富化预算提升到 12000 字符，
采用首／中／尾采样。RSS 启用已有全文提取器；Google News 本身可能仍仅
提供标题和短摘要，不会把短摘要伪装成已阅读全文。模型输出上限为 8192
tokens；此值控制生成长度，与输入字符预算不同。

## 专利公开日期校验

主通道解析 Google Patents 返回的公开日，支持 `YYYY-MM-DD` 与 `YYYYMMDD`。
缺失或非法时尝试读取对应专利原始页面。备用搜索只接受 Google Patents
规范域名和专利路径，随后必须访问该专利页面核对公开号、公开日期和申请人。

无法确认公开日期、早于采集窗口或晚于当天的专利均不进入候选池。
检索时间、申请日、优先权日以及搜索摘要中的日期均不能替代公开日。
公开日只有日精度，因此按 UTC 日历日期包含窗口首日。
不同公开号或 DOI 的文献不会因为讨论同一种技术而被语义去重合并。

旧日报中的以下两项可验证为历史公开，不能作为 2026-10-28 新增专利：

- [CN119734755A](https://patents.google.com/patent/CN119734755A/zh)：公开日 2025-04-01。
- [CN103587576A](https://patents.google.com/patent/CN103587576A/zh)：公开日 2014-02-19。

## 查看每条内容为什么被筛掉

正常运行：

```bash
uv run horizon --config data/config.icar.json --hours 24
```

同一次运行生成：

- `data/summaries/horizon-YYYY-MM-DD-zh.md`：读者使用的日报。
- `data/diagnostics/horizon-YYYY-MM-DD.md`：各板块筛选数量与逐条去留理由。
- `data/diagnostics/horizon-YYYY-MM-DD.json`：原始内容、评分结果、阈值、配额和富化失败详情。

诊断区分低于阈值、分析失败、同事件重复、复评后落选、配额限制和入选。
采集完成及评分完成后分别保存中间结果；后续阶段失败时仍可检查已有输入。
诊断按 UTC 日期命名，同一天重跑会更新同名文件。

扩大窗口和降低相关内容的门槛会增加本地推理用时。需要调节时，优先修改
信息源查询、`max_results`、窗口和限额，再根据诊断决定是否改变评分阈值。

## 资讯为空时的一次兜底

底盘配置已启用 `processing.news_recovery`。定时任务和 CLI 完整运行中，
如果 `icar-info` 首轮没有入选资讯，会在富化、生成和投递之前执行一次兜底。
如果资讯已通过评分、只是受总量或板块配额限制，则不触发补采。

处理顺序如下：

1. 只重试首轮报告为失败、且路由到资讯板块的信息源，不重新抓取论文或专利。
2. 最多处理 5 条分析失败或接近阈值的资讯，分析失败项优先。近阈值指
   `max(3, 入选阈值 - 1) <= 分数 < 入选阈值`。尝试用现有安全全文提取器
   补充正文；已有有效评分的条目只有获得更完整正文后才复评，避免反复打分碰运气。
   分析失败项即使取不到正文也可重试评分。单条全文提取最多等待 30 秒。
3. 仍无达到阈值的资讯时，通过已启用、路由到资讯的 Google News 来源执行
   配置中的分主题补充查询。原有 Google News 未启用时，不会自动启用它。
4. 重试采集与补充查询合计最多新增分析 20 条；按 ID 和规范化 URL 去重，
   丢弃采集窗口之外及晚于本轮兜底起点的内容。评分后继续执行同事件去重和原有配额。

整个过程不降低入选阈值，也不扩大原有来源的回看窗口。比如全局 24 小时、
Google News 单独 72 小时的配置，补采仍使用原有的 72 小时范围；
`--hours 168` 的每周运行则仍使用 168 小时。兜底只进行一轮，
最终仍没有合适资讯时保留空板块说明，统一生成和投递一次。

配置示例：

```json
{
  "processing": {
    "news_recovery": {
      "enabled": true,
      "max_reanalysis_items": 5,
      "max_new_items": 20,
      "queries": [
        "\"线控转向\" OR \"steer-by-wire\"",
        "\"线控制动\" OR \"电子机械制动\" OR \"brake-by-wire\"",
        "\"主动悬架\" OR \"后轮转向\" OR \"扭矩矢量\"",
        "\"整车运动控制\" OR \"vehicle motion control\" OR \"底盘域控\""
      ]
    }
  }
}
```

这是局部配置示例，添加到现有 `processing` 中即可。`enabled: false` 关闭兜底；
省略此配置时默认关闭，以保持其他 Profile 的原有行为。
资讯板块未配置入选阈值（`threshold: null`）时不执行此兜底。
`max_reanalysis_items` 支持 0～20，`max_new_items` 支持 1～100；
`queries` 最多 8 条，每条最多 500 字符。空列表表示不进行分主题补充搜索，
仍允许失败来源重试和候选复评。

同一次运行的诊断 JSON 增加 `news_recovery`：包含是否触发、执行轮数、
原阈值、首轮逐条决策、新增候选 ID、复评前后分数、采集结果及异常。
Markdown 诊断同步展示摘要。原始采集报告保留，重试结果单独记录，
不会在同一次运行里覆盖首轮的去留原因。

当前兜底接入定时任务／CLI 完整流程；MCP 分阶段接口仍按调用者显式指定的阶段执行，
不会在筛选阶段隐式联网补采。信息源内部若将异常转换为空列表，首轮采集报告
可能无法区分“来源无结果”和“来源失败”；资讯仍为空时仍可通过分主题补采尝试恢复。

新增及直接相关的 36 项测试覆盖空采集恢复、阈值保持、复评预算、重复与日期过滤、
失败保留和单次投递。扩展的 97 项回归中 91 项通过，6 项因当前仓库仅保留底盘
Profile、缺少旧测试所需的 `tech-news` Profile 而失败。真实信息源与模型的恢复率
尚未实测；上述测试使用模拟采集和模型结果，不发送真实邮件。
